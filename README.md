# 质见 · 售后质量管理与8D分析

当前本机版：**4.2.0**。完整服务端、前端、自动测试、Windows 部署脚本与使用说明均在本仓库。

## 两种运行方式

- `local-app/`：本机／公司内网应用，Node.js 24.22.1 及以上 24.x，Express、SQLite、真实账号和后端权限校验。
- `dist/`：原 Render 公网演示站的静态页面。仅用于演示，不等同于本机后端版，不接入公司业务数据。

## 从源码运行

1. 安装 Node.js 24.22.1 或更新的 24.x。
2. 在 `local-app` 执行 `npm ci`，安装锁定版本的依赖。
3. 执行 `npm test`。测试仅创建独立模拟数据库，禁止访问正式环境。
4. 源码预览：在 `local-app` 执行 `node scripts/seed-preview.mjs --data data/test`，再执行 `npm start`，打开 `http://127.0.0.1:3868/`。初始化只针对独立测试目录，不覆盖已有记录。
5. 完整离线包已包含运行时和依赖，Windows 上双击 `启动测试版.cmd`，默认打开3870端口。

不要直接双击 `dist/index.html` 来测试真实账号权限。

## 本版操作

- 跟进概览集中显示当前账号的待分配、待确认、待完成事项，点击直接定位。
- 质量工程师可在 D1—D8 提前分派；责任人按本报告内自己的任务顺序办理，九宫格在原卡片显示已提交并开放下一项，其他任务提交后进入下一项。查看权限与办理权限分开。
- D3 以数量和返工任务判断进度，不再要求填写临时遏制摘要。
- D2 自动展示来源基础信息，质量工程师分派，变更管理员填报编号及数量。

## 审查入口

先阅读 `4.2.0九宫格与审查修复.md`、`4.1.1-D2更正说明.md`、`4.1.0更新与审查核对.md` 与 `公司部署与DeepSeek交接.md`。重点审查 `local-app/lib/`、`local-app/server.mjs`、`local-app/public/`、共享引擎 `dist/analysis-core.js`／`dist/analysis-workflow.js` 和 `local-app/test/`；单独检查 `dist` 无法评价真实账号与后端权限。

测试包、数据库、账号密码文件、真实附件、PDF 与备份不提交到 Git。Git 保存代码版本，数据库和附件需独立备份与恢复。

具体使用见 `开始使用.md`。本机测试与正式部署必须使用不同数据目录，企业微信当前仅模拟，不发送真实消息。
